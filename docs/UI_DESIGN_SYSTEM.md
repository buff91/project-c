## 콘셉트

**토치스톤(Torchstone)** — 씬의 공식을 UI에 그대로 적용한다:

> **차가운 청흑 바탕 + 국소 앰버 광원 + 틸 신호색 1개.**

- 바탕은 씬의 어둠과 같은 **청흑**(웜 브라운 금지 — 씬과 온도가 충돌한다)
- 프레임·구조물은 **국소광에 데워진 표면** — 판타지에선 횃불빛 받은 돌, 포스트아포에선
  비상등에 데워진 콘크리트/철골. 같은 웜 그레이·토프 토큰(`--pc-stone*`)을 공유한다.
- **골드/앰버**(`--pc-gold`/`--pc-torch`)는 "현재·선택"과 인공 광원 단 한 곳에만
  (현재 층, 선택 슬롯, 선택 액션 / 비상등·표시등)
- **틸/아이스**는 시스템·물·얼음, 그리고 postapoc의 **이상(異常) 신호**(균열·SF), **하트 레드**는 HP

> 이름은 "Torchstone"을 유지하되(브랜드), postapoc 맥락에선 **"emergency-lit concrete"**로
> 읽는다. 재료 어휘만 바뀌고 토큰·컴포넌트는 동일하다.

### HUD 이원화 (v1.2의 핵심 규칙)

| 구분 | 스타일 | 대상 |
|------|--------|------|
| **인게임 상시 HUD** | **플레이트** — `--pc-void` 0.78 + 1px `--pc-stone-dim` | 바이탈, 계기 묶음(층 스택+미니맵), 메시지 로그, 하단 레일 |
| **메뉴·모달** | 창 크롬 (`pc-window`) | 인벤토리, 조합, 설정, 확인, 결과 화면 |
| **월드 문맥 팝업** | 투명 배경의 방사형 육각 셀 | 플레이어/오브젝트 상호작용 |

컨셉 아트가 이미 그려둔 UI 어휘(하트·다이아)를 시스템으로 승격한 것. **씬이 주인공** — 인게임 패널은
화면 가장자리에 붙고 중앙을 비운다. **창 크롬 자체는 금지가 아니다. 금지는 씬 중앙을 가리는 것이다.**

> **왜 바뀌었나**(2026-07-29, 사용자 결정): 원래 규칙은 "인게임 상시 HUD = 프레임 없는 플로팅"이었다.
> 실제로 그렇게 만들었더니 하트는 맨 스프라이트, 층 정보는 맨 텍스트, 미니맵은 1px 박스, 상태 칩은
> 좌측 보더 플레이트로 **크롬 어휘가 여섯 갈래**가 되어 HUD가 하나의 시스템이 아니라 잔해처럼 읽혔다.
> 사용자가 "창이 떠도 되는데 시인성이 너무 떨어진다"고 규칙을 완화했다. 몰입보다 시인성이 앞선다.
> 지금 어휘는 **정확히 둘**이다 — 상시 HUD는 플레이트, 모달은 창(`.pc-window`). 셋째를 만들지 않는다.

### 아이콘·텍스트 선택 규칙

아이콘은 장식이 아니라 **반복 인식 비용을 줄이는 도구**다. 모든 항목을 아이콘으로
치환하지 않고 정보 성격에 따라 아래 셋 중 하나를 고른다.

| 표현 | 사용하는 항목 | 규칙 |
|------|---------------|------|
| **아이콘만** | 설정, 메뉴, 좌/우 회전처럼 보편적이고 반복되는 도구 | 툴팁과 접근성 이름 필수. 의미가 문화권이나 게임 규칙에 의존하면 사용 금지 |
| **아이콘 + 텍스트** | 소모품+수량, 백팩, 대기, 전투 자세, 문맥 행동 | 아이콘은 종류를, 텍스트는 현재 상태·수량·동사를 맡는다 |
| **텍스트만** | 층/높이, 턴·상태 메시지, 발견 카드, 설명·경고, 파괴적 확인 | 오해 비용이 큰 정보에는 상징 해독을 요구하지 않는다 |

같은 행동을 화면 여러 곳에 중복하지 않는다. 설정·메뉴는 상단 도구, 소모품은 하단
퀵바, 전투·대기·문맥 행동은 하단 행동 도크, 플레이어 팝업은 그 행동들의 포인터 접근
대안으로 역할을 고정한다. 디버그 FOV는 전투 도크가 아니라 미니맵 도구에 둔다.

### 뜨는 UI의 우선순위

1. **월드 선택/조준** — 타겟 라벨은 UGUI, 투척 가능 칸은 바닥 범위 데칼. 비차단.
2. **문맥 행동 팔레트** — 플레이어/오브젝트 가까이에 아이콘+동사로 표시. 선택 가능한
   행동만 강조하고 메뉴·설정 같은 전역 도구는 넣지 않는다.
3. **발견 카드·전투 피드백** — 1회성, 자동 닫힘, 입력 비차단.
4. **인벤토리·설정·확인 모달** — 화면 중앙 창 크롬, 입력 차단. 한 번에 하나만 연다.

`Esc`는 항상 가장 위의 임시 UI 하나만 닫는다. 팝업을 닫은 같은 입력으로 게임 메뉴를
새로 열지 않는다. 파괴적 선택은 아이콘만으로 축약하지 않고 동사형 텍스트 버튼과 결과
설명을 함께 둔다.

### 인터랙션 피드백

- 아이콘 전용 도구는 한 번 클릭하면 즉시 실행하고 툴팁에 단축키를 병기한다.
- 토글은 클릭 즉시 아이콘·레이블·색을 함께 바꾼다. 색만으로 상태를 전달하지 않는다.
- 월드 조준은 대상 선택 → 타일 마커/범위 확인 → 실행의 2단계다.
- 투척 아이템을 선택하면 설명 문장을 상시 띄우지 않고 실제 유효 칸을 낮은 알파로 표시한다.
  행동 결과 피드백은 3초 뒤 닫고, 지금 실행할 수 없는 상시 튜토리얼 문장은 HUD에 남기지 않는다.
- 인벤토리는 슬롯 클릭=선택, 우측 텍스트 버튼=사용/조준이다. 자동 선택된 첫 슬롯을
  다시 눌렀다는 이유로 소모품을 즉시 사용하지 않는다.
- 비활성 행동은 수량 0처럼 이유를 알아야 하는 경우 흐리게 유지하고, 현재 문맥에 아예
  없는 행동은 숨긴다.
- 누른 상태는 1px 하강과 명도/불투명도 변화로 즉시 응답한다.

## 타이포그래피 — Galmuri9, 정수 배율

- 폰트: **Galmuri9** (`UI/Fonts/Galmuri9.ttf`, SIL OFL 1.1 — 라이선스 동봉). `DesignSystem.uss`의 `:root`에서 전역 지정.
- **크기는 9의 정수 배율만**: `--pc-fs-1`(9) 캡션·레이블·버튼 / `--pc-fs-2`(18) 주요 수치 / `--pc-fs-3`(27) 데미지·타이틀 / `--pc-fs-4`(36) 메인 메뉴 타이틀 / `--pc-fs-6`(54) 층 전환 연출.
- **하드 규칙 둘** — `UssTypographyTests`가 USS 소스를 직접 읽어 강제한다:
  - **합성 볼드 금지.** Galmuri9은 Regular 단일 페이스라 `-unity-font-style: bold`를 주면 Unity가
    래스터를 굵게 합성해 획이 번지고 자간이 틀어진다. 강조는 색(`--pc-gold`/`--pc-dim`)이나 크기로.
  - **소수점 자간 금지.** `letter-spacing: 0.5px` 류는 어떤 배율에서도 도트 격자에 안 떨어진다.
    정수값은 36~54px 대형 활자의 연출로만 허용한다.
- **논리 캔버스 640×360** — `PanelSettings`는 `ConstantPixelSize`이고 배율은 `UiPanelScale`이 정한다:
  `Scale(w,h) = max(1, floor(min(w,h) / 360))`. **짧은 축 기준**이라 세로 화면에서도 성립한다.

  | 화면 | 배율 | 논리 캔버스 | 9px → 실제 px |
  |---|---|---|---|
  | 1280×720 · 1920×1080 · 2560×1440 | 2·3·4 | **640×360** | 18·27·36 |
  | 1366×768 | 2 | 683×384 | 18 |
  | 2560×1080 | 3 | 853×360 | 27 |
  | 1280×1024 | 2 | 640×512 | 18 |
  | 1080×1920 / 1170×2532 (세로) | 3 | 360×640 / 390×844 | 27 |
  | 844×390 (가로 폰) | 1 | 844×390 | 9 |

  PC 검증 3종이 **전부 정확히 640×360**에 떨어진다 — 배치 하나, 해상도 분기 없음.
  정직한 대가: 960×540은 배율 1이라 HUD가 절반이 된다. **PC 최소 지원 창은 1280×720**이다.

> **한 줄 정정(실측, `docs/captures/spike-*.png`)**: 정수 배율은 픽셀 폰트를 선명하게 만들지 **않는다**.
> UI Toolkit 텍스트 생성기가 글자마다 제 서브픽셀 위상에서 따로 래스터화하기 때문이다.
> 640×360으로 간 이유는 선명도가 아니라 **같은 논리 px가 화면에서 커지기** 때문이다(2560×1440에서 +29%).
- 선명도가 부족하면 에디터에서 Galmuri9로 Font Asset을 만들어(Raster 모드) `-unity-font-definition`에 연결한다.

## 입력 크기와 눌림 피드백

- `hud-desktop` 16:9 상시 HUD는 640×360 논리 캔버스에서 **4px 간격 그리드**, 바깥 여백 8px,
  하단 레일 높이 24px, 공용 액션·상단 도구 아이콘 10~12px,
  하트 12×11px을 기준으로 한다.
  ⚠ 구역 좌표는 `hud-root`의 **보더 박스** 기준이다 — UI Toolkit의 Yoga는 CSS와 달리
  절대 배치 자식에 부모 padding을 적용하지 않는다(실측). 여백 8은 구역마다 명시적으로 쓴다. 화면이 넓어져도 컨트롤을 확대하지 않고 바깥 여백만
  늘린다. 층 정보와 미니맵은 하나의 우상단 계기 묶음으로 취급한다.
- `ui-touch`의 일반 버튼·토글·드롭다운·슬라이더는 논리 56px 이상을 유지한다.
- 인벤토리처럼 밀집된 격자는 최소 44px, 6×4 백팩의 실제 셀은 52px 누름 영역을 사용한다.
  이 수치들은 **540 논리 높이** 시절 기준이다. 캔버스가 360 으로 줄어 같은 물리 크기는 56→37 · 44→29 · 52→35 로 환산된다(× 360/540). 실제 값은 백팩 셀 피치 40(누름 36)이라 환산 하한을 넘는다 — 화면 비율로는 오히려 넓어졌다.
- 짧은 화면에서는 버튼을 줄이지 않고 본문을 스크롤한다. 헤더와 완료/닫기 동작은 고정한다.
- 누른 상태는 1px 하강과 명도/불투명도 변화로 즉시 응답하되, 레이아웃 크기는 바꾸지 않는다.

## 컴포넌트 클래스 (DesignSystem.uss)

## 사용 규칙

1. UXML에서 `DesignSystem.uss`를 **화면별 USS보다 먼저** 로드.
2. 화면별 USS는 **레이아웃만**. 색·폰트·프레임은 `pc-*` 클래스와 `var(--pc-*)`.
3. **골드 글로우/강조는 화면에 한 곳만** (현재 층 또는 선택 대상).
4. UGUI(월드 앵커: 적 HP바, 데미지 숫자, 상호작용 팝업)도 같은 팔레트. 데미지 숫자는 `--pc-fs-3` + 하드 섀도.
5. `PrototypeHUD.uss`는 v1.2 토큰으로 이관 완료 (레이아웃 유지, 색만 교체).

## 스프라이트 적용 현황과 남은 승격 (USS 한계)

USS에는 box-shadow가 없어 프레임·글로우·눈금은 도트 9-slice 스프라이트로 승격한다
(`Tools/ArtPipeline/build_ui_nineslice_v1.py` 생성, `DesignSystem.uss` §9-slice에 배선):

- 창 크롬의 **깎인 모서리** → ✅ `ui-window-frame.png`(+`-teal`) 9-slice, 패널 채움 baked(진짜 컷코너). `.pc-window`.
- 다이아 현재층/선택의 **골드 글로우** → ✅ `ui-glow-frame.png` 9-slice. `.pc-dia--current`/`.pc-dbtn--selected`/`.pc-slot--selected`.
- 게이지 **세그먼트 눈금** → ✅ `ui-gauge-tick.png` 가로 반복 오버레이(`.pc-bar-ticks`).

> 실 렌더·슬라이스 미세조정은 `DesignSystemGallery`를 UIDocument에 붙여 Unity에서 확인.
> **라이브다.** 던전 모달 카드가 `.pc-window` 9-slice를 쓰고, 상태이상 칩(`.pc-chip--burn/--freeze/--poison`)은
> 던전 HUD 좌상단에 나온다. `.pc-heart`만 쓰던 시절의 "무영향" 메모는 더 이상 사실이 아니다.
- 하트·물약·폭탄·냉기 폭탄 아이콘은 `Art/Runtime` 도트 스프라이트 적용 완료. 검·장화 등 추가 액션 아이콘은 같은 세트에서 확장한다.
- 설정·메뉴·회전·백팩·대기·근접·원거리·상호작용은
  `ui-*.png` 32×32 Torchstone 세트로 마감해 PC HUD에서 24×24로 표시한다.
  UXML은 의미/레이블을 소유하고
  `DesignSystem.uss`의 `.ui-*-icon` 클래스가 그림만 교체한다.
- 문맥 행동 셀은 `ui-action-hex.png` / `ui-action-hex-hover.png` 72×64 프레임을
  사용한다. 프레임은 투명 모서리·금속 베벨·작은 체결부만 소유하고, 아이콘과 짧은
  레이블은 런타임 View가 올린다. 최종 Aseprite 프레임으로 파일만 교체할 수 있다.
- 다이아는 최종적으로 `rotate` 대신 스프라이트로 (픽셀 그리드 보존)

v1.5의 문맥 행동은 플레이어 중심을 비운 6방향 육각 링으로 표시한다. 셀 안에는
24×24 아이콘과 짧은 동사/수량만 넣고 전체 설명은 툴팁으로 보낸다. 문맥에 없는 행동은
해당 방향을 비워 공간 메뉴의 위치 기억을 보존한다. 사각 창 배경은 사용하지 않는다.
최종 M4 월드 팝업은 같은 구조를 UGUI로 이관한다. HUD와 허브의 화면별 USS는
`--pc-*` 토큰을 덮어쓰지 않으며, 양쪽 모두 같은 청흑 패널·금속/석재 프레임·골드
선택·틸 시스템 규칙을 따른다.

## 메시지 로그 · 상태이상 칩 (640×360에서 추가)

- **메시지 로그** (`#message-log`, 좌하단 208px 플레이트) — `MessageLog`(Core, 용량 4)가 링으로 보관하고
  연속 중복은 `"text ×N"`으로 접는다. 최신 줄은 이름을 유지한 `#feedback-chip`/`#status-label`이 맡아
  3초간 `--pc-text`로 밝고, 그 뒤 `--pc-dim`으로 내려앉되 **줄은 남는다**. 지난 줄은 컨트롤러가
  `.message-line`으로 그 앞에 깔며 줄 높이를 12px로 못박는다(Galmuri9 기본 줄 상자가 9px 글자에 18px라서).
  데이터는 원래부터 `InteractionFeedback`이 턴마다 쏘고 있었고 3초 뒤 버려질 뿐이었다.
- **상태이상 칩** (`#status-chips`, 바이탈 바로 아래) — 활성 상태만 `화상 2` 꼴로 그린다.
  빈 행이면 높이 0이라 평상시 비용이 없다. 포만(`#hunger-label`)은 **경고 이상일 때만** 네 번째 칩으로
  합류한다 — 95% 시간 동안 정보가 없는 "포만"을 상시로 띄우던 자리다.
- **층 스택** (`#floor-stack`, 우측) — 층마다 6×3 눈금 하나, 피치 5px. 세로 배치는 **공간 인덱스**
  (FloorIndex) 기준이라 상승·하강 던전이 같은 코드로 성립하고, 밝기만 **진행 인덱스** 기준이다
  (현재=`--pc-gold` / 탐색함=`--pc-stone-dim` / 미도달=`--pc-inset`). ▲▼ 캡은 스택의 **양 끝**을
  가리키며 그 끝에 서 있으면 사라진다. 던전 HUD에서 골드는 여기 하나뿐이다.


## 화면공간 비네트 (`.pc-vignette`)

- `Art/Runtime/ui-vignette.png` 96×96 9-slice, `-unity-slice-*: 24`. 중앙 48×48이 **완전 투명**이라
  늘어나는 건 투명한 부분뿐이고, 디더 도트는 모든 패널 배율에서 크기를 유지한다
  (`.pc-window`가 이미 쓰는 수법). 생성기는 `Tools/ArtPipeline/build_ui_nineslice_v1.py`.
- 세 화면 루트(`hud-root`/`hub-root`/`main-menu-root`)의 **첫 자식**으로 둔다 = 모든 HUD 콘텐츠 뒤.
  월드만 어둡게 하고 UI는 건드리지 않는다. `picking-mode="Ignore"`.
- 최대 알파 0.70, `--pc-void` 단색. 화면공간에서 월드 **뒤에** 합성되므로 FOV 틴트 시스템
  (`SpriteRenderer.color` 곱)과 싸우지 않는다.
- **URP 포스트프로세싱 Vignette를 쓰지 않는 이유**: ① 1비트 도트 위의 매끄러운 방사형
  그라디언트는 스프라이트 게임에 셰이더를 덧댄 것처럼 읽힌다 — 디더 어휘에 합류하지 못하고
  싸운다. ② 씬 clear color가 이미 `#05070C`(=`--pc-void`)라 곱셈 비네트가 어둡게 할 것이 거의
  없다 — 실제 효과는 전부 밝은 방 가장자리에 나타나고 그건 스프라이트가 훨씬 싸게 낸다.
  ③ 카메라 `m_RenderPostProcessing` + 씬 3개마다 Volume + 전면 blit이 필요하다.
