# Project-C UI · 적 로스터 재설계 제안 v1

> 상태: **UI Field Deck v1 작업 트리 반영 / 적 6종 방향·상태·새 추적 드론·팔레트 Unity 승인**
> 기준일: 2026-08-04
> 목표: 현재 게임 규칙과 정보 구조를 유지하면서, UI를 픽서용 전술 장비로 재정의하고
> 폐 아케이드 복합타워의 적을 하나의 설명 가능한 점유 생태계로 묶는다.
>
> 구현 주의: 이 문서는 현재 작업 트리의 UXML/USS·glyph·배치/큐 헬퍼와 아이템 소스 교체를
> 반영한다. 2026-08-04 교체한 추적 드론과 차콜·건메탈 중심 팔레트는 정식 Aseprite 방향·상태 시트,
> Unity PC 런타임 카탈로그 화면, 전체 EditMode/PlayMode 회귀까지 검수했다.

## 1. 진단과 현재 해소 상태

### UI 기준선 오류 — 배선 해소, 화면 확인 대기

- 진단 당시 `IsoPrototype.unity`의 `PrototypeHudController.mobileHudAsset`과 `desktopHudAsset`이 둘 다
  비어 있었고, `IsoPrototypeSceneBuilder`도 공용 `PrototypeHUD.uxml`만 UIDocument에 연결했다.
- 현재 작업 트리는 씬과 빌더 양쪽에서 `PrototypeHUD.Mobile.uxml`·`PrototypeHUD.Desktop.uxml`을
  명시적으로 연결한다. 빠진 wrapper를 조용히 재생성하지 않도록 빌더는 필수 자산 로드를 실패 처리한다.
- 따라서 코드 경로상 공용 fallback 대신 Desktop 규격을 선택할 수 있다. 다만 실제 2560×1440 q0
  캡처는 아직 만들지 않았으므로 새 기준선의 화면 결과는 미확정이다.

### 아이콘 제작 계보 오류 — PC 공용 glyph 교체, 화면 확인 대기

- 구 9개 액션 아이콘은 418px AI 셀을 32px로 BOX 축소한 결과였다.
- 색상만 쿨 계조로 옮겼고, 작은 입체 금속 소품·다단 셰이딩·반투명 알파가 남아 있다.
- 실제 PC HUD에서 다시 비정수 축소하면 선 굵기와 세부가 불규칙하게 탈락했다.
- 현재 작업 트리의 `build_field_deck_glyphs_v1.py`는 9종을 표시 크기와 같은 12×12 hard-alpha,
  쿨 스틸 3색 이내 픽토그램으로 직접 만든다. Desktop USS만 `ui-field-*.png`를 고르고 Mobile은
  기존 32×32 세트를 유지한다. 생성 계약 파일은 추가됐지만 Unity 화면 판독성은 아직 확인하지 않았다.

### 적 제작 계보 오류 — 해소

- 진단 당시 `actor-goblin/skeleton/slime`은 폐 아케이드 이전의
  `anomalous transit facility` 소스였고, 감시자 recipe에는 `anomalous organic core`가 남아 있었다.
- 현재 작업 트리는 일반 적 5종과 보스 `actor-grave-warden`의 정적 폴백뿐 아니라 4방향
  idle/walk/attack/hit/fall/death Aseprite 타임라인도 새 점유 세력 실루엣으로 고정했다. 여섯 자산은
  하드 알파·제한 팔레트·2×2 클러스터·발 기준선 계약을 공유한다.
- 로스터 전부는 작은 적색 IFF, 기업 잉여 장갑, 노출 배선이라는 시각 DNA를 공유한다.
- 구 범용 생성기는 적 PNG를 더는 소유하지 않으므로 녹색 고블린·해골·생물형 오즈가 재생성으로
  되살아나지 않는다.

## 2. UI 단일 방향 — Field Deck

정체성은 **“픽서 청부업자가 수리해 쓰는 전술 옵틱 / salvaged field deck”**으로 고정한다.
금속 액자나 돌판을 흉내 내지 않고, 장비가 투사하는 평면 정보층으로 보이게 한다.

- 바탕: 저알파 청흑 플레이트.
- 구조: 1px 쿨 그레이 선, 열린 모서리, 한쪽만 잘린 비대칭 코너.
- 크롬: 짧은 마젠타 데이터 틱만 사용한다. 넓은 마젠타 면은 금지한다.
- 현재/선택: 앰버 한 곳.
- 판정: 실제 유효 경로·상호작용·관찰 상태에만 틸을 사용한다.
- 비활성 도구: 프레임 없는 회색 glyph. hover/선택 때만 배경과 색 틱이 나타난다.
- 하단: 여러 버튼 상자가 아니라 `자원 도크`와 `행동 도크` 두 레일.
- 우상단: 미니맵·층·보기·회전을 하나의 얇은 계기로 통합한다.
- 디버그 FOV 전환은 개발 계약상 유지하되 일반 플레이 시안에서는 숨긴다.

채택 시안:

- 전체 화면: `project-c-field-deck-hud-concept-v3.png`
- glyph 문법: `project-c-field-deck-icons-concept-v1.png`

v1~v2는 탐색·계약 검수본으로만 남긴다. 최종 v3는 8F→B2 층 축, `현재 B2 · 보기 B2`,
위/현재/아래 보기, 10/10 체력 5칸 완충, 중립 근접 액션을 실제 HUD 계약에 맞췄다.
B2에서 불가능한 `▼`는 28% 밝기로 비활성화했고, 로그는 208×52 논리 px의 4줄 footprint를 확보했다.

### 현재 작업 트리의 이식 범위

- 좌상 바이탈은 160px 안에 5개 분절 HP 셀을 두고, 상단 중앙 과도 패널은 256px로 제한했다.
  우상은 층 눈금·`▲/◆/▼`·현재/보기·회전·56×56 미니맵을 한 176×104 계기로 묶었다.
  좌하 로그는 208×52, 하단은 자원 184×24와 행동 268×24 두 레일이다.
- 공용 UXML의 `name=`과 콜백 계약은 유지하고 Desktop USS만 Field Deck 배치를 소유한다.
- `.pc-plate`의 `ui-bracket-frame.png`는 12×12 9-slice다. 열린 모서리는 쿨 스틸, 마젠타는
  각 상단 코너 옆의 붙은 2px 데이터 틱만 맡고, 늘어나는 위 변은 저알파 스틸 헤어라인이다.
- 바이탈·우상 계기·보스/발견 과도 패널·로그·자원/행동 레일이 같은 브래킷 문법을 쓴다.
- 긴 문맥 동사와 화면 모서리에서도 액션 휠 전체가 HUD를 덮지 않도록 `HudWheelPlacement`가
  여섯 셀 footprint를 패널 안으로 clamp하고 현재 보이는 고정 HUD bounds를 피한다.
- 던전 입장과 수직 경로 발견은 같은 과도 패널에 FIFO로 쌓인다. 보스 패널이 우선하고, 중단된
  활성 카드는 즉시 숨긴 뒤 보스가 닫히면 남은 노출 시간부터 다시 표시한다. 일반 열림/닫힘은
  USS opacity/translate 0.16초이며, 보스 우선 전환은 두 패널이 겹치지 않도록 즉시 suppress한다.

## 3. 아이콘·아이템 소스 계약

- PC 공용 HUD glyph는 네이티브 12×12로 직접 그린다. 32px 대형 그림을 축소하지 않는다.
- 표시 크기와 클릭 영역을 분리한다. glyph는 작게 유지해도 버튼 hit area는 현재 계약을 보존한다.
- hard alpha, 1px 논리 선, 고립 1px 노이즈 0.
- 아이콘당 3~5색 이내. 중립 2색 + 역할 accent 1색을 원칙으로 한다.
- normal / selected / disabled는 가능하면 USS tint와 배경 상태가 소유한다.
- 작은 물건 그림이 아니라 표지 픽토그램으로 만든다.
- 근접은 검이 아니라 `동력 프라이바 + 충격 브래킷`, 원거리는 총이 아니라
  `조준점 + 전기 아크`, 상호작용은 `손 + 접촉 셰브론`으로 읽힌다.
- 최종 에셋 승격 전 hard alpha·색 수·클러스터·체크인 재현성 테스트를 추가한다.

현재 `settings/menu/rotate-left/rotate-right/backpack/wait/melee/ranged/interact` 9종이
`ui-field-*.png`로 생성된다. 같은 12×12로 표시하되 버튼 picking 영역은 기존 계약을 유지한다.
normal/hover/selected/disabled 차이는 glyph 변형 파일을 늘리지 않고 USS 색·배경·하단 틱이 맡는다.

아이템 쪽에서는 자연물/판타지 결정처럼 읽히던 두 소스를 같은 산업 장비 어휘로 교체했다.

| 런타임 슬롯 | 새 화면 정체성 | 유지되는 계약 |
|---|---|---|
| `item-herb` | **지혈 패치** — 봉인 포장·의료 표식·주황 압박 스트랩 | `ItemKind.Herb`, 슬롯명, 64×64 마감, 바닥 피벗, 조합 재료 역할 |
| `item-frost-shard` | **냉각 코일** — 검은 하우징·구리 루프·시안 냉각선 | `ItemKind.FrostShard`, 슬롯명, 64×64 마감, 바닥 피벗, 냉기 조합 재료 역할 |

원본은 `item-sources-v3/item-{herb,frost-shard}-source-v3.png`, conform 경로는 기존
`process_items_v3.py`다. 새 아이템 종류나 효과를 추가한 것이 아니며 Unity 실화면 판독성은 아직 미확정이다.

## 4. 첫 던전 적 생태계

가칭 **폐 아케이드 점거 수거단**이 건물의 청소·경비·셔터·운송 기계를 탈취해 함께 운용한다.
인간과 기계가 모두 빛바랜 갈라진 셰브론과 작은 적색 IFF 램프를 공유한다.
사이버펑크는 전신 네온이 아니라 기술 섬유, 기업 시설 잔해, 불법 개조 배선에서 낸다.

| 코드 역할 | 새 화면 정체성 | 게임플레이 실루엣 계약 |
|---|---|---|
| `Goblin` | **점거군 돌격병** | 가벼운 2.5~3등신 인간형, 호흡기·소형 기업 잉여 장갑·직선 충격봉. 방패 없음 |
| `Slime` | **기업 추적 드론** | 낮은 사족 보안 하운드, 쐐기형 센서 헤드·노출 서보 척추·손상된 제압제 주입턱. 전투 로봇으로 즉시 판독 |
| `Skeleton` | **기업 진압 로봇** | 넓은 어깨 장갑·무거운 구동계·좁은 카메라 슬릿. 일반 적 중 유일한 탱커 |
| `Slinger` | **기업 보안 사수** | 밀폐 기업 방탄복·불투명 바이저·견착 소형 아크 카빈. 원거리 역할이 총열로 읽힘 |
| `GraveWarden` | **감시자** | 불법 전투 외골격을 두른 사이버사이코 집행관. 인간형 질량·센서 마스트·붉은 사이버 광학안 |
| `ArcDrone` | **합선 검사 드론** | 침수된 금고 전용. 좌우 절연 플로트와 하부 방전 코일, 등반 불가 실루엣 |

`ArcDrone`은 첫 던전 세력 라인업이 아니라 두 번째 원정지의 전용 적으로 유지한다.
따라서 채택 로스터에서는 의도적으로 제외한다.

초기 비례 시안: `project-c-arcade-occupation-roster-concept-v3.png`.
현행 추적 드론 정체성과 적군 팔레트는 `project-c-corporate-pursuit-drone-source-v2.png` 및
`process_arcade_occupation_actors_v1.py`가 우선한다.

왼쪽부터 원정자 스케일 기준, 점거군 돌격병의 구 기반형, 폐기된 청소 크롤러 기반형,
기업 진압 로봇의 기반형, 기업 보안 사수의 기반형, 감시자의 기반형이다.
v1~v2는 군용 장비·거대 보스·역할 중복·신호색 충돌을 확인한 탐색본으로만 남긴다.
v3의 청소 크롤러와 갈색 중심 재료 배분은 2026-08-04 폐기했다. 현행 적은 차콜·건메탈을 주조로,
시안/마젠타를 센서·케이블에만 국소 배치하고 적색 IFF를 작은 점으로 제한한다. v3는 투척수의 정지 케이블을 캔버스 안에 감았으며,
감시자 원본 폭을 70~76px 목표로 낮춰 런타임 1.3배 확대 후에도 한 타일 질량을 지킨다.

## 5. 시안 느낌을 실제 화면에 보존하는 조건

UI는 레이아웃과 재질감 모두 실제 화면에서 시안의 약 85~90%까지 직접 재현할 수 있다.
차이는 Unity 표현력 때문이 아니라 제작 단위에서 생기므로 아래 조건을 지킨다.

- 복구된 PC wrapper로 fallback HUD가 아니라 Desktop 규격을 기준으로 비교한다.
- 패널은 큰 PNG 액자를 얹지 않고, 12×12 9-slice가 열린 쿨 스틸 모서리와 짧은 data tick만 제공한다.
- glyph는 시안 보드를 잘라 쓰지 않고 12×12 런타임 격자에서 직접 생성한다.
- 텍스트와 수치는 생성 이미지의 글자를 복사하지 않고 실제 UXML 데이터 바인딩이 소유한다.
- 몬스터는 시안 PNG를 축소하지 않고 실루엣·재료 면적·색 분배를 96×128 원본에 옮긴다.
- 첫 검수는 정적 남향 한 프레임을 B2의 실제 q0~q3/FOV/선택 마커 위에서 비교한다.

시안과 런타임 캡처를 2560×1440에서 좌우 비교해, `화면 중심을 침범하지 않는가`,
`12px glyph가 한눈에 구분되는가`, `액션 휠이 HUD와 화면 밖을 침범하지 않는가`,
`연속 입장/발견 카드가 덮어쓰이지 않는가`, `적 역할이 무채색 실루엣만으로 구분되는가`,
`캐릭터 발이 타일에 접지되는가`를 통과 기준으로 삼는다.

현재 이 기준은 **검증 계획**이다. 캡처 파일이나 전체 테스트 결과가 생기기 전에는 통과로 바꾸지 않는다.

## 6. 채택 후 구현 순서

1. PC HUD wrapper 배선 복구 — **작업 트리 반영**, 현재 자산 기준 캡처는 대기.
2. Field Deck USS 스킨과 네이티브 12×12 glyph 9종 적용 — **작업 트리 반영**, 2560×1440 탐색 상태 검증은 대기.
3. 조준·수직 보기·액션 휠 상태 확장 — 수직 보기/Field Deck 액션 glyph와 안전 배치, 입장/발견 큐까지
   **작업 트리 반영**. 실제 조준·모서리·연속 카드 화면 검증은 대기.
4. `Goblin + Slime`에서 시작해 일반 적 5종과 감시자의 남향 정적 프레임 제작 — **작업 트리 반영**.
5. 적 6종을 실제 런타임 슬롯에 연결 — **작업 트리 반영·Unity PC 런타임 카탈로그 승인**.
6. 승인된 정적 실루엣을 4방향·`idle/walk/attack/hit/fall/death` 24태그로 확장 — **완료**.
