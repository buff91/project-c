# Project-C UI · 적 로스터 재설계 제안 v1

> 상태: **시안 / 런타임 미반영**
> 기준일: 2026-08-02
> 목표: 현재 게임 규칙과 정보 구조를 유지하면서, UI를 픽서용 전술 장비로 재정의하고
> 폐 아케이드 복합타워의 적을 하나의 설명 가능한 점유 생태계로 묶는다.

## 1. 현재 화면을 그대로 다듬으면 안 되는 이유

### UI 기준선 오류

- `IsoPrototype.unity`의 `PrototypeHudController.mobileHudAsset`과 `desktopHudAsset`이 둘 다 비어 있다.
- `IsoPrototypeSceneBuilder`도 공용 `PrototypeHUD.uxml`만 UIDocument에 연결한다.
- 따라서 현재 q0 캡처는 `PrototypeHUD.Desktop.uss`의 104px 미니맵·24px 하단 도크가 아니라,
  공용 160px 미니맵·34px 하단 레일이 4배 확대된 fallback 화면이다.
- 시각 재작업 전 PC wrapper 배선을 복구하고, 같은 2560×1440에서 새 기준 캡처를 만든다.

### 아이콘 제작 계보 오류

- 현재 9개 액션 아이콘은 418px AI 셀을 32px로 BOX 축소한 결과다.
- 색상만 쿨 계조로 옮겼고, 작은 입체 금속 소품·다단 셰이딩·반투명 알파가 남아 있다.
- 실제 PC HUD는 10/12/24px로 다시 비정수 축소해 사용하므로 선 굵기와 세부가 불규칙하게 탈락한다.
- UI용 정식 Aseprite 원본이 없고, 현재 테스트도 크기만 확인한다.

### 적 제작 계보 오류

- `actor-goblin/skeleton/slime`은 폐 아케이드 이전의 `anomalous transit facility` 소스에서 왔다.
- 구 프롬프트는 `cyberpunk neon`을 금지하고, 감시자 recipe에는 `anomalous organic core`가 남아 있다.
- 인간 약탈자·일반 박스 로봇·눈 달린 슬라임 사이에 같은 세력 또는 시설의 시각 DNA가 없다.
- `arcDrone`과 `graveWarden` 카탈로그 슬롯은 비어 있어 서로 다른 해상도의 절차 폴백을 사용한다.

## 2. UI 단일 방향 — Field Deck

정체성은 **“픽서 청부업자가 수리해 쓰는 전술 옵틱 / salvaged field deck”**으로 고정한다.
금속 액자나 돌판을 흉내 내지 않고, 장비가 투사하는 평면 정보층으로 보이게 한다.

- 바탕: 저알파 청흑 플레이트.
- 구조: 1px 쿨 그레이 선, 열린 모서리, 한쪽만 잘린 비대칭 코너.
- 크롬: 짧은 마젠타 데이터 틱만 사용한다. 넓은 마젠타 면은 금지한다.
- 현재/선택: 앰버 한 곳.
- 판정: 실제 유효 경로·상호작용·관찰 상태에만 틸을 사용한다.
- 비활성 도구: 프레임 없는 회색 glyph. hover/선택 때만 배경과 색 틱이 나타난다.
- 하단: 여러 버튼 상자가 아니라 `자원 도크`와 `행동 도크` 두 레일.
- 우상단: 미니맵·층·보기·회전을 하나의 얇은 계기로 통합한다.
- 디버그 FOV 전환은 개발 계약상 유지하되 일반 플레이 시안에서는 숨긴다.

채택 시안:

- 전체 화면: `project-c-field-deck-hud-concept-v3.png`
- glyph 문법: `project-c-field-deck-icons-concept-v1.png`

v1~v2는 탐색·계약 검수본으로만 남긴다. 최종 v3는 8F→B2 층 축, `현재 B2 · 보기 B2`,
위/현재/아래 보기, 10/10 체력 5칸 완충, 중립 근접 액션을 실제 HUD 계약에 맞췄다.
B2에서 불가능한 `▼`는 28% 밝기로 비활성화했고, 로그는 208×52 논리 px의 4줄 footprint를 확보했다.

## 3. 아이콘 계약

- HUD glyph는 네이티브 12×12 또는 16×16로 직접 그린다. 32px 대형 그림을 축소하지 않는다.
- 표시 크기와 클릭 영역을 분리한다. glyph는 작게 유지해도 버튼 hit area는 현재 계약을 보존한다.
- hard alpha, 1px 논리 선, 고립 1px 노이즈 0.
- 아이콘당 3~5색 이내. 중립 2색 + 역할 accent 1색을 원칙으로 한다.
- normal / selected / disabled는 가능하면 USS tint와 배경 상태가 소유한다.
- 작은 물건 그림이 아니라 표지 픽토그램으로 만든다.
- 근접은 검이 아니라 `동력 프라이바 + 충격 브래킷`, 원거리는 총이 아니라
  `조준점 + 전기 아크`, 상호작용은 `손 + 접촉 셰브론`으로 읽힌다.
- 최종 에셋 승격 전 hard alpha·색 수·클러스터·체크인 재현성 테스트를 추가한다.

## 4. 첫 던전 적 생태계

가칭 **폐 아케이드 점거 수거단**이 건물의 청소·경비·셔터·운송 기계를 탈취해 함께 운용한다.
인간과 기계가 모두 빛바랜 갈라진 셰브론과 작은 적색 IFF 램프를 공유한다.
사이버펑크는 전신 네온이 아니라 기술 섬유, 기업 시설 잔해, 불법 개조 배선에서 낸다.

| 코드 역할 | 새 화면 정체성 | 게임플레이 실루엣 계약 |
|---|---|---|
| `Goblin` | 수거꾼 / 셔터 러너 | 가벼운 2.5~3등신 인간, 비대칭 수거 배낭, 짧은 동력 프라이바. 방패 없음 |
| `Slime` | 누출 크롤러 | 낮고 넓은 고장 청소봇, 파열된 세정액 블래더와 끌리는 호스. 생물 얼굴 없음 |
| `Skeleton` | 차단 경비기 | 낮고 넓은 셔터 장갑, 소형 구동계, 좁은 카메라 슬릿. 일반 적 중 유일한 탱커 |
| `Slinger` | 볼트 투척수 | 같은 수거단의 마른 인간형, 치켜든 손목 케이블 발사기와 대각 탄자 밴돌리어 |
| `GraveWarden` | 감시자 | 화물 로더·개찰기·CCTV를 합친 비대칭 문지기, 넓은 하부와 가는 센서 마스트 |
| `ArcDrone` | 합선 검사 부표 | 침수된 금고 전용. 좌우 절연 플로트와 하부 방전 코일, 등반 불가 실루엣 |

`ArcDrone`은 첫 던전 세력 라인업이 아니라 두 번째 원정지의 전용 적으로 유지한다.
따라서 채택 로스터에서는 의도적으로 제외한다.

채택 시안: `project-c-arcade-occupation-roster-concept-v3.png`

왼쪽부터 원정자 스케일 기준, 수거꾼, 누출 크롤러, 차단 경비기, 볼트 투척수, 감시자다.
v1~v2는 군용 장비·거대 보스·역할 중복·신호색 충돌을 확인한 탐색본으로만 남긴다.
최종 v3는 적 활성 신호를 작은 적색 IFF로 제한하고, 투척수의 정지 케이블을 캔버스 안에 감았으며,
감시자 원본 폭을 70~76px 목표로 낮춰 런타임 1.3배 확대 후에도 한 타일 질량을 지킨다.

## 5. 시안 느낌을 실제 화면에 보존하는 조건

UI는 레이아웃과 재질감 모두 실제 화면에서 시안의 약 85~90%까지 직접 재현할 수 있다.
차이는 Unity 표현력 때문이 아니라 제작 단위에서 생기므로 아래 조건을 지킨다.

- PC wrapper를 먼저 복구해 fallback HUD가 아니라 Desktop 규격을 기준으로 비교한다.
- 패널은 PNG 액자를 얹지 않고 USS의 1px 선·열린 모서리·짧은 data tick으로 만든다.
- glyph는 시안 보드를 잘라 쓰지 않고 12×12/16×16 Aseprite 원본으로 다시 그린다.
- 텍스트와 수치는 생성 이미지의 글자를 복사하지 않고 실제 UXML 데이터 바인딩이 소유한다.
- 몬스터는 시안 PNG를 축소하지 않고 실루엣·재료 면적·색 분배를 96×128 원본에 옮긴다.
- 첫 검수는 정적 남향 한 프레임을 B2의 실제 q0~q3/FOV/선택 마커 위에서 비교한다.

시안과 런타임 캡처를 2560×1440에서 좌우 비교해, `화면 중심을 침범하지 않는가`,
`10px glyph가 한눈에 구분되는가`, `적 역할이 무채색 실루엣만으로 구분되는가`,
`캐릭터 발이 타일에 접지되는가`를 통과 기준으로 삼는다.

## 6. 채택 후 구현 순서

1. PC HUD wrapper 배선 복구 → 현재 자산 그대로 기준 캡처.
2. Field Deck USS 스킨과 네이티브 glyph 9종을 한 화면에 적용 → 2560×1440 탐색 상태 검증.
3. 조준·수직 보기·액션 휠 상태를 같은 언어로 확장.
4. 적은 첫 구간에 가장 자주 나오는 `Goblin + Slime` 남향 정적 프레임만 먼저 제작한다.
5. 두 대표 적을 실제 B2에 연결해 원정자 대비 배율·FOV·접지·q0~q3를 검증한다.
6. 통과 후 `Skeleton + Slinger`, 마지막에 감시자를 만든다.
7. 정지 실루엣이 승인된 뒤에만 4방향과 idle/walk/attack/hit/death 애니메이션으로 확장한다.

이번 시안 단계에서는 UXML/USS, 카탈로그, 런타임 스프라이트를 변경하지 않는다.
