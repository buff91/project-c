5 · 지금 / 제안

위는 현재 빌드 캡처, 아래는 같은 1280×720에서의 제안이다. 픽셀 대 픽셀로 겹쳐 보라고 같은 폭으로 세로로 쌓았다. 바뀐 것은 크기만이 아니라 어휘의 수다 — 여섯 갈래 크롬이 하나로 줄었다.

이 시안이 지키는 규칙

항목규칙이유
논리 캔버스640×360 (배율 2 / 3 / 4) 에디터 실측: 같은 2560×1440에서 HUD 잉크 폭이 361px → 465px, +29%. 시인성은 여기서 나온다
폰트 크기9 · 18 · 27 · 36 · 54 만 Galmuri9은 9px 페이스다. 스케일을 하나로 묶어 위계를 만든다
굵기합성 볼드 금지 Galmuri9에 볼드 페이스가 없어 Unity가 래스터를 번지게 합성한다
자간소수점 letter-spacing 금지 어떤 배율에서도 도트 격자에 안 떨어진다
크롬플레이트 / 창, 딱 둘 맨 스프라이트·맨 텍스트·좌측 보더 칩이 섞여 잔해처럼 읽혔다
골드우상 계기의 현재 위치만 현재 층 눈금과 플레이어 마커 중심 외 행동·턴 강조로 번지지 않는다

실측으로 기각된 가설: 정수 패널 배율이 도트를 살린다(배율 3에서 같은 글자 폭이 6px·5px로 오히려 갈렸다) · fontRenderingMode가 도트를 살린다(캡처 바이트 동일). UI Toolkit은 글자마다 제 서브픽셀 위상에서 따로 래스터화하므로 배율로는 못 고친다. 그래서 이 시안이 파는 것은 선명도가 아니라 상대 크기·대비·그룹핑이다. 증거: docs/captures/spike-*.png.

스프라이트·폰트는 실제 런타임 에셋(Galmuri9 사용 글자 서브셋 인라인). 비네트와 앰버 광원 웅덩이는 Phase 5의 제안을 CSS로 근사한 것이다 — 엔진에서는 9-slice 스프라이트와 기존 GridLighting으로 구현한다.
