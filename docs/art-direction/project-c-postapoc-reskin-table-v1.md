# Project-C 포스트 아포칼립스 리스킨 표 (초안 v1)

> **상태**: 설계 초안. **코드는 아직 안 바꿨다.** 실제 스프라이트/문자열 교체 + Play 검증은
> 별도 작업(로컬)에서 한다. 이 표는 "무엇을 무엇으로" 확정하는 설계 SSOT다.
> **원칙**: 스탯·AI 행동·데이터 계약·정렬·요소 반응 로직은 **불변**. 표시 이름 + 스프라이트 +
> 서사 정체만 교체한다(=리스킨). 근거 코드 경로를 각 항목에 적었다.

## 0. 두 가지 축 (먼저 정할 것)

### 0-a. 코드 ID vs 표시 이름
내부 아키타입 키(`"Goblin"/"Skeleton"/"Slime"`, 보스 바운티 키 `"warden"`)는
`MonsterRoster.cs`·`RunTelemetry.cs`·테스트가 문자열로 참조한다.
- **(A · 권장) 코드 ID 유지 + 표시만 교체** — `RunSummary.cs` 한글 문구 + 스프라이트만 교체.
  로스터/텔레메트리/테스트 무수정. 프로토 최소 리스크.
- **(B) 코드 ID까지 개명** — 콘텐츠가 늘어난 뒤 일괄 진행 권장.

### 0-b. 던전마다 얼굴이 다르다 (핵심)
SF냐 유기냐를 **세계 전체로 못 박지 않는다.** "이상 미궁"은 미궁마다 정체가 다른
이상 현상이므로, **던전이 테마 프로파일 하나를 고르고**, 그 프로파일이 공유 아키타입 각각의
스킨을 결정한다. → 같은 `Skeleton`이 던전 A에선 "경비 드론", 던전 B에선 "변이 허스크".
**시스템은 하나, 얼굴만 던전별.** (SPD의 단일 연속 던전과 차별화되는 지점)

> **스코프**: 현재 던전은 1개(`collapsed-transit`, 프로파일 A)뿐이다. **지금은 패턴 확정 +
> 던전 1만 구체화**하고 B/C는 문서 슬롯으로 둔다. 다던전은 첫 던전 데이터 확보 후(GDD §11).

## 1. 던전 테마 프로파일

구현 경로: `Scripts/Core/DungeonCatalog.cs`가 던전 데이터(층 수·보스)를 이미 소유하므로,
여기에 **`themeProfile` 필드**를 데이터로 추가하는 게 자연스럽다(코드 작업=로컬/후속).
프로파일은 (i) 아키타입 스킨셋, (ii) 강조 요소 반응, (iii) 광원/소품 무드를 묶는다.

| 프로파일 | 결 | 레퍼런스 | 강조 요소 | 상태 |
|----------|-----|----------|-----------|------|
| **A. 기계·시설** | 콘크리트·전기·네온 (SF 살짝) | 벙커·통신탑·주유소 (ref 01·02·05) | **감전**(침수+전선)·폭발(연료) | ✅ 던전 1 확정 |
| **B. 잠식·생물** | 덩굴·포자·변이 (유기) | 담쟁이 폐건물·덩굴 편의점 (ref 03·04) | 중독/포자·화상(마른 덩굴) | 🔲 후속 슬롯 |
| **C. 침수·냉각** | 물·냉각재·산성 | (추후) | **빙결**(냉각재)·감전(침수) | 🔲 개요만 |

### 프로파일별 아키타입 스킨 (스탯·AI는 §2, 여기선 얼굴만)

| 공유 아키타입 | A. 기계·시설 | B. 잠식·생물 | C. 침수·냉각 |
|---------------|--------------|--------------|--------------|
| `Slime` (약·다수) | 누출 오염 슬러지 | 점균/포자낭 | 산성 웅덩이 |
| `Goblin` (근접·최다) | 약탈자(넝마+고철) | 감염 약탈자(포자) | 침수 부랑자 |
| `Skeleton` (탱커·심층) | **낡은 경비 드론** | **변이 허스크** | 부식 잠수체 |
| 보스 `warden` (문지기) | 감시자(개조 기계) | 미궁의 태(유기 코어) | 수몰 관리자 |
| 광원/소품 | 방폭등·네온·드럼통 불 | 생물 발광·포자 안개 | 비상 조명·수면 반사 |

> 던전 1은 A로 확정. B/C 칸은 후속 던전이 생길 때 이 표에서 그대로 끌어 쓴다.

출처: `DungeonCatalog.cs`(`DefaultId`, 설명/보스 문자열), `BountyRules.cs`(보스 키 `"warden"`).

> **환승역 → 폐병원 재변경 (v0.3.2, 2026-07-25)**: 환승역은 **지하로 내려가는 공간**이라
> v0.3에서 재정의한 건물형 수직성 어휘(계단실·붕괴 구멍·**창문**·엘리베이터 통로)와 어긋난다.
> 특히 **외벽 창문**(GDD §5.2 — 깨면 낙하로 이어지는 수평 시야 포털)이 지하에서는 성립하지 않아
> 이미 구현된 `WindowRules`의 절반이 첫 던전에서 죽는다. 상세 근거는 GDD §10.1.
>
> **확정된 아트는 거의 그대로 쓴다.** 버티컬 슬라이스 1의 환경 세트는 균열 콘크리트 바닥 ·
> 손상 콘크리트 벽 패널 · 앰버 비상등 · 중철 방폭문 · 마모 콘크리트 서비스 계단으로,
> **전부 폐병원 서비스 구역으로 그대로 읽힌다.** 선로·전동차·개찰구 같은 환승역 전용 에셋은
> 제작된 적이 없다("플랫폼/환승벽"은 설명 문구였을 뿐이다). 병원 고유 소품(위생 타일·들것·커튼·
> 수술등·엘리베이터 통로)은 **교체가 아니라 추가**이며 지상층부터 붙인다.

## 6. 리스킨 실행 순서 (로컬 작업용 체크리스트)

> 범위 원칙(GDD §3): 한 번에 전부 갈지 말 것. **던전 1(프로파일 A) 한 화면분**부터.

1. §0-a **(A) 코드 ID 유지** 채택 확정.
2. (선택) `DungeonCatalog.cs`에 `themeProfile` 필드 추가 — 프로파일 A 하나만 배선.
3. `RunSummary.cs` 표시 문구(고블린/해골/슬라임/묘지기) → 프로파일 A 스킨 이름.
4. `DungeonCatalog.cs` 던전 이름·설명·보스 표시 문자열 교체(ID는 (A)면 유지).
5. 스프라이트: 몬스터 4종 + 허브 광원/소품(드럼통 불·비상등·이상 균열)부터.
6. `env-*` 타일 리스킨(art-direction 문서의 51슬롯 매핑표) — 던전 1 한 층 분.
7. **Play 캡처(모바일 세로·PC 가로) + EditMode 646 / PlayMode 1 회귀.** ← 검증 게이트.
